# POSIX Message Queue BULK_PEEK for CRIU

This repository contains a proof-of-concept (PoC) kernel patch and validation
test suites for introducing the `MQ_IOC_BULK_PEEK` ioctl to Linux POSIX message
queues.

This work is part of a Google Summer of Code (GSoC) effort related to
checkpoint/restore in userspace (CRIU).

## Architecture Design

To improve resilience against denial-of-service patterns and low-memory pressure, the kernel implementation applies the following design choices:

1. **Byte-level chunking (pagination):** Uses `start_offset` and `MQ_PEEK_FLAG_HAS_MORE` to support incremental reads of large messages across `msg_msgseg` boundaries.
2. **Hard-capped kernel buffer:** The implementation caps internal `kzalloc` allocation at 8 KB (`MAX_PEEK_BUF_SIZE`), regardless of the user-requested size.
3. **Strict 8-byte alignment:** Each entry in the peek buffer is 8-byte aligned to avoid layout disclosure and preserve 32/64-bit compatibility.
4. **Capability-gated access:** Requires `CAP_CHECKPOINT_RESTORE` or `CAP_SYS_ADMIN` (namespace-aware via `ns_capable`).

## v2 Changes (vs. kernel_patch/)

The v2 series in `kernel_patch_v2/` addresses LKML review concerns:

- **`MQ_IOC_BULK_PEEK` ioctl number**: `('M', 1)` → `('M', 0x80)`. Avoids the
  densely-conflicted `'M' 0x00-0x16` range (mtd-abi, megaraid_sas, fsl-diu-fb).
  Registers `'M' 0x80-0x8F` for future POSIX mqueue ioctls.
- **`msg_copy_part_to_kernel()`**: dropped `EXPORT_SYMBOL_GPL` (single-subsystem
  helper, both call sites built-in under `CONFIG_POSIX_MQUEUE`); changed
  `u8 *dest` → `void *dest`; removed dead `WARN_ON_ONCE` (caller already
  enforces the bound); added kernel-doc.
- **`mqueue_bulk_peek()`**: split into `mqueue_peek_fill_buf()` (acquires
  `info->lock`, packs the kernel buffer) plus a thin outer shell (validate /
  alloc / `copy_to_user` / free). Main function dropped from ~150 to ~60 lines.
- **`Signed-off-by`**: capitalised author (`Sunchao Dong`).
- **Selftest `setuid(65534)`**: replaced with `getpwnam("nobody")` + fallback
  to `getuid() + 1`.
- **Selftest `MQ_IOC_BULK_PEEK` macro** in all three test files synced to
  `('M', 0x80)`.

`checkpatch.pl --git HEAD~3..HEAD`: patches 1 and 2 fully clean, patch 3 emits
only a cosmetic `MAINTAINERS need updating` warning for the new selftest files.
## Boot Patched Kernel in QEMU

### Kernel build prerequisites

Make sure `CONFIG_CONFIGFS_FS=y` is set before building, otherwise systemd
inside the guest fails `sys-kernel-config.mount` and drops to emergency mode:

```bash
./scripts/config --enable CONFIGFS_FS
make olddefconfig && make -j$(nproc) bzImage
```

### Disk image quirks (syzkaller-style trixie)

The minimal Debian image referenced below (`trixie.img`, generated by syzkaller's
`create-image.sh`) is missing `dhclient` and uses `/dev/root` in `/etc/fstab`,
so the default networking + remount-fs paths fail. Fix by adding a static
`systemd-networkd` profile and masking the broken units:

```bash
sudo mount -o loop trixie.img /mnt/img
sudo tee /mnt/img/etc/systemd/network/10-default.network <<'EOF'
[Match]
Name=en* eth*

[Network]
Address=10.0.2.15/24
Gateway=10.0.2.2
DNS=10.0.2.3
EOF
sudo mkdir -p /mnt/img/etc/systemd/system/sockets.target.wants
sudo ln -sf /lib/systemd/system/systemd-networkd.service \
    /mnt/img/etc/systemd/system/multi-user.target.wants/systemd-networkd.service
sudo ln -sf /lib/systemd/system/systemd-networkd.socket \
    /mnt/img/etc/systemd/system/sockets.target.wants/systemd-networkd.socket
sudo ln -sf /dev/null /mnt/img/etc/systemd/system/networking.service
sudo ln -sf /dev/null /mnt/img/etc/systemd/system/systemd-remount-fs.service
sudo sed -i 's|^/dev/root|#/dev/root|' /mnt/img/etc/fstab
sudo umount /mnt/img
```

`10.0.2.15/24` is the address QEMU's slirp normally hands out via DHCP, so the
host port-forward (`hostfwd=tcp::10022-:22`) reaches the guest sshd directly.

### QEMU launch

```bash
qemu-system-x86_64 \
  -kernel /root/linux/arch/x86/boot/bzImage \
  -append "root=/dev/vda console=ttyS0 rw nokaslr" \
  -drive file=trixie.img,format=raw,if=virtio \
  -nographic \
  -m 2G \
  -smp 2 \
  -net nic,model=virtio \
  -net user,hostfwd=tcp::10022-:22 \
  -virtfs local,path=/root/mycriu/criu,mount_tag=host_criu,security_model=passthrough,id=host_criu \
  -virtfs local,path=/root/linux/tools/testing/selftests/mqueue,mount_tag=host_tests,security_model=passthrough,id=host_tests
```

SSH in (key generated by `create-image.sh` next to the image):

```bash
ssh -i trixie.id_rsa -p 10022 root@localhost
```

Inside the guest:

```bash
mkdir -p /mnt/tests /mnt/criu
mount -t 9p -o trans=virtio,version=9p2000.L host_tests /mnt/tests
mount -t 9p -o trans=virtio,version=9p2000.L host_criu  /mnt/criu
```

## Building Tests (VM Environment)

Either build statically on the host before booting (binaries land in the same
directory the guest 9p-mounts), or build dynamically inside the guest:

```bash
cd tools/testing/selftests/mqueue
gcc -static -o mq_chunk_tests  mq_chunk_tests.c  -lpthread -lrt
gcc -static -o mq_stress_tests mq_stress_tests.c -lpthread -lrt
gcc -static -o mq_edge_tests   mq_edge_tests.c   -lpthread -lrt
```

All tests must run as root on a kernel with the patch applied.

The chunk test queues 100 KB + 50 KB messages, which exceeds the default
`RLIMIT_MSGQUEUE` of 800 KB. Bump it before running any of the tests:

```bash
ulimit -q unlimited
```

## Gotchas

- **Stale CRIU binary**: a pre-built `criu/criu` checked into a working tree
  may have been compiled from a branch without mqueue support. Verify with
  `strings criu/criu | grep -ic pmq` — a non-zero count means the binary has
  the dump/restore code. Rebuild on `my-gsoc-private-work` if it's zero.
- **9p clock skew**: building CRIU from a host-shared 9p mount produces
  `Clock skew detected` warnings; if the build appears to no-op, `touch` the
  file you changed to force a rebuild.
- **Stale `.d` files** referencing an older GCC path (e.g. `gcc/.../13/...`)
  on a host with a newer GCC will break the build. Clear them:
  `find . -name "*.d" | xargs grep -l "gcc/.*/13" | xargs rm`.
- **CRIU-side ioctl number** (`criu/posix-mqueue.c`) must be in sync with the
  kernel UAPI. v2 of the kernel patch uses `_IOWR('M', 0x80, ...)`; older
  CRIU code defining `('M', 1)` will silently fail with `-ENOTTY` on a v2
  kernel.
